# Boreal updater

`boreal-updater` enforces a strict `/etc/nixos` downstream contract: `update`
syncs `/etc/nixos` to its upstream `https://` tracking branch and prebuilds the
host NixOS generation, and `schedule` queues `boreal-updater.service` to drain
active pipelines and switch to that exact prebuilt closure once quiescent. When
`system.switch.enable` is `false` (such as in disposable `mkVm` guests) or when
any drain, database, or recovery check is uncertain, activation remains
fail-closed (`phase=blocked`) with no operator override. Automatic garbage
collection is never enabled or invoked.

## Policy and `/etc/nixos` contract

- `/etc/nixos` must be a root-owned downstream Git checkout (`uid 0`, not
  writable by group or others) on a checked-out branch tracking an `https://`
  remote branch (without credentials, query, or fragment) whose committed
  `flake.lock` pins `boreal` without local `file://` or `path` overrides.
- `/etc/boreal/updater.yaml` (`0400 root:root`, generated by `boreal.updater`)
  defines:
  - `projectDir`: `/etc/nixos`.
  - `host`: `config.networking.hostName` (`nixosConfigurations.<host>`).
  - `allowSwitch`: `config.system.switch.enable`.
  - `workerUnits`: `boreal-worker-<user>-<worker>.service` units, plus
    `boreal-schedule-<user>-<worker>.service` when that worker enables
    `schedule`, stopped before
    the final post-drain quiescence check.
  - `brokerSocket`: `/run/boreal/updater.sock`.

## Commands

Root CLI (`boreal-updater`):

```text
boreal-updater update
boreal-updater schedule
boreal-updater run
boreal-updater recover
boreal-updater status
```

Restricted SSH admin shell (`boreal-admin` / `boreal-admin-ctl`):

```text
updater update
updater schedule
updater recover
updater status
```

## Sync, prebuild, drain, and recovery protocol

1. **Sync & prebuild (`update`)**: verifies `/etc/nixos` and `/etc/nixos/.git`
   ownership/permissions, resolves the checked-out branch's upstream `https://`
   remote and branch, fetches and hard-resets `/etc/nixos` to the upstream
   commit (`-c core.hooksPath=/dev/null`), verifies `flake.lock` hygiene, builds
   `git+file:///etc/nixos?rev=<rev>#nixosConfigurations.<host>.config.system.build.toplevel`
   with `--no-update-lock-file --no-write-lock-file` to a distinct
   `/var/lib/boreal-updater/attempt-*/result` GC root, and records `prebuilt`
   (or `blocked` when `allowSwitch` is `false`).
2. **Schedule switch (`schedule`)**: verifies `phase=prebuilt`, `allowSwitch`,
   the prebuilt GC root, and an open broker admission gate, persists
   `phase=scheduled`, releases `/var/lib/boreal-updater/lock`, and starts
   `boreal-updater.service` (`systemctl --no-block start`) so drain and switch
   run asynchronously in the background.
3. **Close gate (`run`)**: persists `Gate::Closed` in `boreal-broker`, waits for
   in-flight `run` calls to finish recording, pauses unpaused Temporal
   schedules across all user namespaces (recording which schedules were paused),
   and tracks schedule-reported executions.
4. **Authoritative drain (`run`)**: polls `boreal-broker` until every tracked
   execution, schedule execution, child workflow, and continue-as-new descendant
   (found via strongly-consistent `DescribeWorkflowExecution` and
   `GetWorkflowExecutionHistory`), every live worker gRPC task lease, and
   Temporal's primary PostgreSQL `current_executions` table report zero open
   executions.
5. **Stop workers & re-verify (`run`)**: stops configured `boreal-worker-*`
   units and re-runs `CheckDrain` to ensure no timer or task fired immediately
   prior to worker shutdown.
6. **Exact activation (`run`)**: verifies the GC root symlink still targets the
   exact prebuilt `/nix/store/...` closure, sets `/nix/var/nix/profiles/system`,
   executes `<result>/bin/switch-to-configuration switch` without re-evaluating
   Git or flakes, waits for `temporal.service` and `boreal-broker.service`,
   reopens the gate, and records `phase=activated`.
7. **Recovery (`recover`)**: `boreal-updater.service` sets
   `restartIfChanged = false` and `stopIfChanged = false`. If interrupted during
   `draining` or `activating`, `boreal-updater recover` checks
   `/run/current-system` against `state.result`: completed switches reopen the
   gate and unpause updater-paused schedules, interrupted pre-switch drains
   restore workers and return to `prebuilt` with the gate reopened, and
   uncertain mid-switch states remain `blocked` with the gate closed.

# Boreal updater

`boreal-updater` enforces repository and branch bounds, prebuilds a pinned
downstream lab NixOS closure, coordinates an authoritative admission-and-drain
barrier with `boreal-broker`, and activates the exact prebuilt closure when
safe. When `system.switch.enable` is `false` (such as in disposable `mkVm`
guests) or when any drain, database, or recovery check is uncertain, activation
remains fail-closed (`phase=blocked`) with no operator override. Automatic
garbage collection is never enabled or invoked.

## Policy and downstream target model

`/etc/boreal/updater.yaml` (`0400 root:root`, generated by `boreal.updater`)
defines:

- `repository`: exact `https://` downstream Git repository URL.
- `branch`: optional reviewed branch name (verified via `git fetch` of
  `refs/heads/<branch>` and `git merge-base --is-ancestor <rev>`).
- `host`: expected `nixosConfigurations.<host>` configuration name.
- `allowSwitch`: `config.system.switch.enable`.
- `workerUnits`: `boreal-worker-<user>-<worker>.service` units stopped before
  the final post-drain quiescence check.

Because `main` only ships the Boreal framework, `boreal-updater` always targets
a 40-digit commit on the downstream lab repository whose committed `flake.lock`
pins `boreal` without local `file://` or `path` overrides.

## Commands (root / `boreal-admin-ctl`)

```text
boreal-updater schedule [<https-repo>] <40-digit-commit> [<hostname>]
boreal-updater prebuild
boreal-updater run
boreal-updater recover
boreal-updater status
```

## Admission barrier, drain, and recovery protocol

1. **Prebuild**: verifies `<rev>` on the configured `repository` (and reviewed
   `branch` when set), checks committed `flake.lock` hygiene with
   `--no-update-lock-file --no-write-lock-file`, builds
   `nixosConfigurations.<host>.config.system.build.toplevel` to a distinct
   `/var/lib/boreal-updater/attempt-*/result` GC root, and records `prebuilt`
   (or `blocked` when `allowSwitch` is `false`).
2. **Close gate**: persists `Gate::Closed` in `boreal-broker`, waits for
   in-flight `start` calls to finish recording, pauses unpaused Temporal
   schedules across all user namespaces (recording which schedules were paused),
   and tracks schedule-reported executions.
3. **Authoritative drain**: polls `boreal-broker` until every tracked execution,
   schedule execution, child workflow, and continue-as-new descendant (found via
   strongly-consistent `DescribeWorkflowExecution` and `GetWorkflowExecutionHistory`),
   every live worker gRPC task lease, and Temporal's primary PostgreSQL
   `current_executions` table report zero open executions.
4. **Stop workers & re-verify**: stops configured `boreal-worker-*` units and
   re-runs `CheckDrain` to ensure no timer or task fired immediately prior to
   worker shutdown.
5. **Exact activation**: verifies the GC root symlink still targets the exact
   prebuilt `/nix/store/...` closure, sets `/nix/var/nix/profiles/system`, and
   executes `<result>/bin/switch-to-configuration switch` without re-evaluating
   Git or flakes.
6. **Recovery**: `boreal-updater.service` sets `restartIfChanged = false` and
   `stopIfChanged = false`. If interrupted during `draining` or `activating`,
   `boreal-updater recover` checks `/run/current-system` against `state.result`:
   completed switches reopen the gate and unpause updater-paused schedules,
   interrupted pre-switch drains restore workers and reopen the gate, and
   uncertain mid-switch states remain `blocked` with the gate closed.
